# Deploy record — developer platform, 2026-09-04

## D1 restore point

Taken immediately before `db:migrate:remote`, because migration 0005 rebuilds
`api_keys` (SQLite cannot relax `user_id`'s NOT NULL in place) and D1 migrations
are forward-only. Time travel rolls back the **whole database**, so this is a
last resort, not a routine undo.

```
wrangler d1 time-travel restore chatform \
  --bookmark=00000940-00000000-000050dc-516796bfcc56bf0eaf4be42020848510
```

## Order

1. `pnpm db:migrate:remote` — 0004 (columns, indexes, exports table) then 0005
   (api_keys rebuild + legacy scope backfill).
2. `pnpm apikeys:backfill:remote` — re-encodes pre-plugin key hashes from hex to
   base64url. Idempotent: it selects only 64-character lowercase hex.
3. `pnpm deploy:api`.
4. Verify: `/health`, `/openapi.json`, and an existing key against `/v1/forms`.

Step 2 is belt and braces — verification repairs a straggler on first use — but
running it means no customer pays a one-request latency cost for our migration.

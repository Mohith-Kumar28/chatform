Takes money. Use this whenever the request mentions a price, a fee, a ticket, a deposit or a UPI id — never a text question asking them to confirm they paid.

**How it gets answered** — arrives out of band (an upload, a payment, or a booking).

In a generated draft these arrive as `config` pairs: `method=upi with upi=<vpa like name@bank>, OR method=link with url=<checkout page>; amount=<number>, currency=<3-letter code, INR for rupees>`.

## What you receive

`GET /v1/forms/{id}` and every "next question" projects blocks through `toPublicBlock`. For the example above:

```json title="PublicBlock"
{
  "id": "blk_pay00001",
  "ref": "q_payment",
  "type": "payment",
  "title": "Pay the deposit",
  "required": true,
  "imageKey": null,
  "media": null,
  "currency": "USD",
  "amount": 4900,
  "paymentMethod": "link",
  "url": "https://pay.example.com/x"
}
```

## What you send

### What gets stored

The value is normalised before it is saved, so what you read back is not always what you sent.

| You send | Stored | |
| --- | --- | --- |
| `{"status":"paid","method":"link","reference":"CF-7K2M9X","verified":true}` | `{"status":"paid","method":"link","verified":false,"reference":"CF-7K2M9X","currency":"USD"}` | `verified` is forced to false however it arrives — nothing in this flow talks to a gateway, so nobody can confirm their own payment |

## Errors

| Code | When | Message |
| --- | --- | --- |
| `required` | an empty answer on a required block | This question needs an answer. |
| `type` | `"paid"` | Payment required. |
| `payment_pending` | `{"status":"maybe"}` | Payment has not been completed yet. |
